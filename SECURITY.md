# Security Policy

## Supported versions

| Version | Security support |
| --- | --- |
| `master` | Supported |
| Latest tagged release | Supported |
| Older releases | Best effort only |

Security fixes are normally developed against `master` and backported only when the maintainer decides a supported release needs a patch.

## Reporting a vulnerability

Do **not** open a public issue for a vulnerability that could enable exploitation, unsafe control, credential exposure, or supply-chain compromise.

Use GitHub's private vulnerability reporting for this repository:

- [Report a vulnerability privately](https://github.com/ImperialSpaceSociety/PicoTracker/security/advisories/new)

Include the affected commit or release, the impacted component, reproduction details, expected impact, and any suggested mitigation. If credentials or other secrets are involved, do not paste them into a public issue or pull request.

The maintainer will triage the report privately, coordinate any fix and disclosure, and credit reporters where appropriate. This project does not promise a fixed response-time SLA.
